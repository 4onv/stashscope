## Three ideas compared

| Idea | Demand | Distinct value | Demo friction | Discoverability | Decision |
| --- | --- | --- | --- | --- | --- |
| StashScope | Direct stash-transfer fix plus independent shared-stash incidents | Stable stash identity with per-path evidence across linked destinations | One command, generated repository, no account | Clear Git/stash/worktree search intent | Build |
| Worktree overlap map | Parallel agent worktree activity | Low: Grove and herdr-collide already inspect overlapping changes | Easy temporary fixture | Crowded established tools | Reject |
| General worktree doctor | Nov 3 stale marker issue #4683 | Low: existing topology/config diagnostics and Worktrunk status | Easy, but many platform edge cases | Clear problem with direct competition | Reject |

The portfolio's first comparable observation showed no star or fork growth and no open
issues on its four existing projects. There is no measured traction leader yet. Selection
therefore uses concrete demand and low demo friction; there is no claimed user validation.

## Existing alternatives

- [git-stashman](https://github.com/skeate/git-stashman) previews contents, offers
  apply/pop/drop, and already warns about applying in the current directory. StashScope's
  focus is the cross-worktree evidence matrix and stable commit ID; it does not replace a TUI.
- [gsm](https://github.com/shreyazh/gsm) offers stash browsing, search and mutations.
- [git-stash-browser](https://github.com/Firehed/git-stash-browser) previews and drops stashes.
- [Grove](https://github.com/NathanDrake2406/grove) and
  [herdr-collide](https://github.com/mcc0x/herdr-collide) are relevant worktree conflict tools,
  which made a generic overlap checker a weak choice.
- [Agent Worktree Doctor](https://github.com/Tinkora/agent_worktree_doctor) already examines
  worktree topology and metadata, which made a generic doctor a weak choice.

These comparisons reflect reviewed README capabilities, not an exhaustive feature audit.
No reviewed stash browser documented this exact cross-worktree matrix. That is a narrow
implementation distinction, not a claim that stash inspection is a new idea.

## First-version boundary

Give users a useful inventory before manually choosing a restoration destination. Preserve
all existing work, resolve a stable stash commit, include tracked/staged/untracked paths,
show local blockers and unsupported states. Do not apply, delete, auto-select a destination,
infer ownership, or promise merge success. The demo data is generated and labeled.
